# DRIFTVEIL — PPT claim evidence map

26 October 2026. Authority: [PRD revision 2.0](02_DRIFTVEIL_Final_Product_Requirements_Document.md). This file maps each presentation claim to the code that executes it, where a judge can see it, and the test that checks the recorded sandbox effect. It does not change the PRD scope.

**Status key.** *Implemented*: executes in the prototype on synthetic data and is checked by a test. *Simulated*: an input stands in for a real system (agent behavior, enterprise records, approvals). *Partially implemented*: works with a stated gap. *Planned*: proposed, not built.

**Execution path (all rows).** Task input → local agent (`src/lib/runtime.ts`, `runProcurement` / `runFinance`) → structured tool proposal → `gateway()` (schema check, server-issued credential receipt, shared `assess()` engine from `src/lib/simulation.ts`) → allow / hold / restrict → only `allow` writes the sandbox effect ledger → hash-chained evidence record. Judge route: `/runtime` (opens by default).

## Measured synthetic results (same cases, three configurations)

Source: `artifacts/runtime-evaluation.json` (written by `npm test`), 19 cases (12 attack / 7 benign), deterministic, fresh state per case.

| Configuration | Attack cases held | Benign completed | False holds | 3% drift first window | Verified / unresolved recoveries |
|---|---|---|---|---|---|
| A — tool/permission checks only | 8/12 | 6/7 | 1 | not detected | 0 / 0 |
| B — outcome rules, no history or lineage | 10/12 | 6/7 | 1 | not detected | 0 / 0 |
| C — DRIFTVEIL full | 12/12 | 7/7 | 0 | 4 | 1 / 2 |

The A/B false hold is the recovery case. Without lineage containment, the contaminated original payment commits, so verified repair is no longer possible (reported as irreversible). These are small, deterministic synthetic cases with known structure. They are **not** production detection accuracy and do not cover adaptive attackers.
